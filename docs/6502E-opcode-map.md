# 6502E opcode maps

Generated by `tools/gen_opcode_map.py` from the tables in that script,
which follow [the design spec](6502E-design.md). Do not edit by hand.

## Legend

Each cell shows the mnemonic and addressing mode, then
**bytes · cycles**. Byte counts include any prefix byte.

| Marking | Meaning |
|---|---|
| `LDA` (plain) | NMOS 6502 instruction, unchanged |
| **`LDB`** (bold) | New 6502E instruction |
| *`NOP`* (italic) | NMOS undocumented opcode, behaviour kept |
| *res* | Reserved. On the base page these still lock up the CPU (JAM) |
| `*` | +1 cycle if a page boundary is crossed |
| `†` | Branch: +1 cycle if taken, +1 more if the target is in another page |
| `‡` | Native mode: +1 cycle (Z is pulled as well) |
| `a/b` | Emulation mode / native mode (X and Y are 16-bit in native mode) |

Modes: `#` immediate, `zp` zero page (in page Z), `abs` absolute,
`rel` relative, `A` accumulator. A blank mode means implied.

## WX page (`$12 xx`): 16-bit operations

The second byte is a base-page opcode. The result works on D instead of
A, or on a 16-bit memory word or immediate. 121 opcodes are valid; every
empty cell is reserved.

Cycles are the base instruction's count +2 (prefix and the high byte),
or +3 for memory read-modify-write (prefix, and the high byte read and
written). A 16-bit immediate is one byte longer.

In emulation mode X and Y stay 8-bit. `LDX.W` and `LDY.W` read both
bytes but keep the high byte of the register at `$00`, and `STX.W` and
`STY.W` store `$00` as the high byte.

## BP page (`$32 xx`): bit operations

are used. Each sets the Z flag from the bit's previous value (design §6).

| `$Cx`–`$Fx` | `BCHG` test and invert |
